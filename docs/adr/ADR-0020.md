# ADR-0020：成本欄位以工具列開關整組隱藏，狀態寫入 UI 偏好

- 狀態：已決定
- 日期：2026-10-20

## 背景

表格目前固定 7 欄，其中股數、平均成本、總報酬都與成本有關。使用者要在報酬顯示切換鈕（`%` / `NT$`）左側加一個「成本」開關，關閉後只留下代號、名稱、現價、今日報酬，方便在不看成本時聚焦當日表現。

需求同時要求開關風格符合現有 app：固定深色、顏色只取自 CSS 變數、字級與間距跟著 `--scale` 等比縮放、紅綠只代表漲跌。

## 決策

1. **新增 UI 偏好 `showCost`**：放進 `UiPreferences`，預設 `true`，寫入 `portfolio.json` 並在啟動時還原。舊檔沒有這個欄位時視為開啟，`schemaVersion` 維持 1。
2. **欄位由 `columnsFor(display, showCost)` 決定**，不是用 CSS 隱藏既有的欄位：
   - 開啟：代號、名稱、股數、平均成本、現價、總報酬、今日報酬。
   - 關閉：代號、名稱、現價、今日報酬（今日報酬仍依 F6 顯示比率或金額）。
3. **總計列同步隱藏成本相關項目**：關閉時只留今日報酬；總成本、總市值、總報酬不顯示，避免成本資訊從總計列漏出。
4. **隱藏欄位的排序鍵要換掉**：`visibleSortKey()` 在關閉時把股數、平均成本、總報酬、市值改成今日報酬，排序方向不變，避免表格依看不到的欄位排序。
5. **開關是自繪的 switch**：`button[role="switch"]` + `aria-checked`，軌道用 `--line-strong` / `--accent`，滑塊用 `--text-faint` / `--bg`，標籤用 `--text-dim`，尺寸乘 `--scale`。不用原生 `input[type=checkbox]`，避免各平台 WebView 的預設外觀與深色主題不一致。
6. **編輯模式不受開關限制**：關閉時股數與平均成本不可就地編輯，刪除與新增仍可用；要改成本欄位先開啟開關。工具列的新增表單照常顯示股數與平均成本，因為新增本來就需要這兩個值。

## 理由

- 用 `columnsFor` 產生欄位，表頭、資料列、空狀態的 `colspan` 與總計列都共用同一個來源，不會出現欄數對不上的情況。
- CSS 隱藏（`display: none`）會留下隱藏的 `th` / `td`，排序、`colspan` 與鍵盤導覽都要另外處理；直接不產生欄位比較單純。
- 總計列若保留總成本與總市值，關閉成本就只擋住表格，資訊仍從下方漏出，與「關閉後只顯示四個欄位」的意圖不符。
- 原生 checkbox 在不同 WebView 版本的尺寸、顏色與焦點外觀不一致；自繪 switch 能完全沿用既有 token 與縮放。

## 後果

- `portfolio.json` 多一個 `showCost`；舊檔缺少或值不是布林時回 `true`。
- 關閉成本時表格變窄，`measureMinSize()` 量到的自然寬度跟著變小，視窗會自動貼合（ADR-0016）。
- 編輯模式下關閉成本只看到「操作」欄的刪除鈕；這是刻意保留的行為，不是缺陷。
- `columnsFor()` 與 `visibleSortKey()` 是純函式，切換後欄位與排序鍵由 vitest 覆蓋；switch 的實際外觀仍需實機確認。

## 曾考慮的替代方案

- **只隱藏股數、平均成本，保留總報酬**：總報酬需要平均成本，留著等於仍暴露成本，與開關名稱不符。
- **關閉時強制使用比率模式**：使用者仍可用 `%` / `NT$` 切換今日報酬，硬改模式會讓開關與顯示切換互相打架。
- **做成獨立「簡易模式」頁面**：多一套表格與重繪路徑，只為了少三個欄位，維護成本過高。
- **用 `hidden` 屬性隱藏欄位**：表頭與資料列都要逐一同步，還要在排序與空狀態另外過濾，容易漏改。
