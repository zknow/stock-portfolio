# ADR-0023：關閉框架的檔案日誌

- 狀態：已決定
- 日期：2026-10-27

## 背景

Neutralinojs 框架會把自己的日誌寫到 `neutralinojs.log`，位置由框架決定，`neutralino.config.json` 沒有路徑選項可以改到 `logs/`。專案的執行期日誌是 `logs/app.log`（ADR-0004、`src/services/logger.ts`），兩者用途不同，並存會讓排查時混淆。

## 決策

1. **`neutralino.config.json` 設定 `logging.writeToLogFile: false`**，框架日誌改寫到標準輸出，不再產生 `neutralinojs.log`。
2. **`logs/` 只保留 `app.log`**，由 `logger.ts` 負責寫入。

## 理由

- 框架檔案路徑不可設定，把檔案「搬」到 `logs/` 需要啟動腳本在框架執行中做檔案操作，且框架持有檔案時搬移會失敗。
- 關閉檔案輸出是唯一能讓 `logs/` 只剩專案日誌的設定，不需要額外腳本。

## 後果

- 框架錯誤只在 `scripts\start.bat` 開啟的主控台或 `neu run` 輸出中可見，不會落盤。
- 排查 `NE_*` 框架錯誤時，需在開發模式下重現；打包後的 exe 不再留下框架錯誤紀錄。
- 專案日誌仍只記錄異常與狀態轉換（見 `docs/requirements.md` §5），不受影響。
