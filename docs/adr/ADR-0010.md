# ADR-0010：Vite 產出放 `build/`，globals 由框架注入

- 狀態：已決定
- 日期：2026-10-16

## 背景

ADR-0005 決定採 TypeScript + Vite，並在後果留下一份 `neutralino.config.json` 串接範例。該範例假設 Vite 產出目錄是 `dist/`，且以 `frontendLibrary.patchFile` 把客戶端程式庫注入 HTML。

P1 實作時確認兩件事：

1. `neu build` 的輸出目錄預設為 `dist/`，可用 `cli.distributionPath` 覆寫（`node_modules/@neutralinojs/neu/src/commands/build.js` 第 24 行）。前端產出若也放 `dist/`，`neu build` 會與它互相覆蓋。
2. `frontendLibrary.patchFile` 是給不使用 `injectGlobals` 的專案用的。`frontendlib.bootstrap` 只在 `patchFile` 存在時才會被呼叫（`src/modules/websocket.js` 第 29 行）。設 `modes.window.injectGlobals: true` 時由框架直接注入，`patchFile` 與 `cli.clientLibrary` 都不需要。

## 決策

1. Vite 的 `build.outDir` 設為 `build/`，`documentRoot` 與 `cli.resourcesPath` 都指向 `/build/`。`dist/` 保留給 `neu build`，不改動 `cli.distributionPath` 的預設值。
2. `modes.window.injectGlobals: true`，不設 `cli.clientLibrary` 與 `frontendLibrary.patchFile`。客戶端程式庫改用 npm 的 `@neutralinojs/lib`，由 Vite 打包。
3. Vite 的 `publicDir` 設為 `resources/`，`resources/**` 原樣複製到 `build/`。視窗圖示路徑因此是 `/build/icons/appIcon.png`。
4. Vite dev server 設 `strictPort: true`，確保 `devUrl` 的埠與 CLI 等待的埠一致。

`neutralino.config.json` 的對應片段：

```json
"documentRoot": "/build/",
"modes": {
  "window": {
    "injectGlobals": true,
    "icon": "/build/icons/appIcon.png"
  }
},
"cli": {
  "binaryName": "stock-portfolio",
  "binaryVersion": "6.10.0",
  "resourcesPath": "/build/",
  "frontendLibrary": {
    "devUrl": "http://localhost:5173",
    "projectPath": "/",
    "initCommand": "npm install",
    "devCommand": "npm run dev",
    "buildCommand": "npm run build"
  }
}
```

## 理由

- 前端產出與發佈產物各有清楚的位置，兩邊都維持慣例名稱：`build/` 是 Vite 專案的慣例產出目錄，`dist/` 是 `neu build` 的預設輸出，也是 `neutralinojs-zero` 的 `.gitignore` 已排除的名稱。
- 改用 `distributionPath` 把 `neu build` 移到別處同樣可行，但要倚賴一個非預設的 key，換不到額外好處。
- `patchFile` 的做法是插入 `<script src="http://localhost:<port>/__neutralino_globals.js">`，由 CLI 在執行期間改寫原始 HTML 並在結束時還原。`injectGlobals` 由框架在 webview 端注入，少一個會被改寫的檔案。實測 dev server 觸發 page reload 後 globals 仍正常注入。
- `publicDir` 指向 `resources/` 讓該目錄保持「其他資源」的語意，同時自動進入打包流程，不需要另寫複製步驟。

## 後果

- `neutralino.config.json` 的 `documentRoot`、`cli.resourcesPath`、Vite 的 `build.outDir` 三者必須一致指向 `build/`。
- `build/` 與 `dist/` 都必須排除版控。
- `resources/` 底下的檔案在正式建置只會被複製，不會被當成原始碼處理。
- 沒有 `patchFile` 就沒有 CLI 的 HTML 改寫與還原，`index.html` 與 `resources/` 在開發期間不會被修改。
- 必須維持 `injectGlobals: true`。若日後關閉，須同時補回 `clientLibrary` 或 `patchFile`。
- `neu build` 只會複製 `bin/` 內實際存在的框架執行檔（`src/modules/bundler.js` 第 143 行有 `existsSync` 檢查），因此只放 Windows 執行檔時只會產出 Windows 版本。

## 曾考慮的替代方案

- **Vite 產出留在 `dist/`，`cli.distributionPath` 設為 `release/`**：可行，但需倚賴非預設 key，且與 `neutralinojs-zero` 既有的 `.gitignore` 慣例不一致。
- **保留 `patchFile` 而不改用 `injectGlobals`**：同樣可用，但 CLI 會在執行期間改寫 `index.html` 再還原，多一個會被改寫的檔案。
- **載入 `cli.clientLibrary` 指定的 `neutralino.js`**：CLI 需從 GitHub Releases 下載該檔，在本機的 proxy 環境下會失敗（背景見 ADR-0009）。
