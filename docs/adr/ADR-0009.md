# ADR-0009：報價傳輸以 `net.get` 為主，`curl.exe` 為備援

- 狀態：已決定
- 日期：2026-10-16

## 背景

ADR-0001 決定以 MIS 為主來源，並把傳輸細節收在 `QuoteProvider` 介面內。P1 建立骨架時發現 `Neutralino.net` 完全不支援 proxy，而本開發機所在的網路直連外網會被防火牆擋下。同一支 MIS 端點的實測結果：

| 呼叫方式 | 結果 |
|---|---|
| `Neutralino.net.get` → `http://127.0.0.1:5173` | 200 |
| `Neutralino.net.get` → `https://mis.twse.com.tw/...` | 20 秒無回應 |
| `curl.exe`，繼承 `HTTPS_PROXY` → 同上 | 0.8 秒，200 |
| `curl.exe --noproxy "*"` → 同上 | 逾時，exit 28 |
| `node fetch` → 同上 | `TypeError: fetch failed` |
| `node fetch` 加 `NODE_USE_ENV_PROXY=1` → 同上 | 200 |

`net.request` 的選項只有 `contentType`、`timeout`、`params`、`headers`、`auth`、`body`、`allowRedirects`、`encodePath`、`keepAlive`，沒有 proxy 欄位，框架也沒有對應的啟動參數。`HTTPS_PROXY` 在本機是機器層級環境變數，任何子行程都繼承得到，`curl.exe` 因此可連外。

## 決策

1. 主傳輸為 `Neutralino.net.get`。
2. 環境變數出現 `HTTPS_PROXY` 或 `HTTP_PROXY` 時，改走 `Neutralino.os.execCommand` 執行 `curl.exe -s -i -m <秒數> "<url>"`。
3. 兩條路徑收在 `src/services/http.ts` 的同一個出口 `getText(url): Promise<{ status: number; body: string }>`，提供給 `MisProvider`、`YahooProvider`、`symbolTable`。provider 不知道實際走哪條路。
4. 首選傳輸在啟動時決定一次並固定，不在每次輪詢重試另一條。
5. 非 Windows 或取不到 `curl.exe` 時只保留 `net.get`。

用 `-i` 讓 `curl.exe` 把回應標頭一併輸出，狀態碼從第一行 `HTTP/1.1 <code>` 取得。不用 `-w "%{http_code}"`，避免 `%` 在 `cmd.exe` 被當成變數展開。

## 理由

- 只用 `net.get`：在公司網路下等於完全沒有報價，違反「即時追蹤股價」的核心需求。
- 只用 `curl.exe`：把桌面應用程式綁死在外部執行檔與 shell 字串解析上，在正常網路環境是不必要的脆弱點。
- 兩條路徑都只是取回一段字串，出口介面可以完全一致，provider 不需分支。
- 以環境變數判斷，避免在需要 proxy 的網路上每一輪都先付出 20 秒逾時。

## 後果

- `src/services/http.ts` 是唯一知道傳輸方式的檔案。provider 只做回應解析。
- `curl.exe` 路徑要自行解析標頭與本文的分界，並處理 Windows 的引號跳脫。URL 一律以雙引號包住。
- `os.execCommand` 沒有逾時參數，逾時由 `curl.exe -m` 負責。
- `nativeAllowList` 已含 `os.*` 與 `net.*`，不需調整。
- 打包後的應用程式只額外依賴 `curl.exe`，Windows 10 1803 起內建，不需安裝。
- 兩條路徑都要有測試。`curl.exe` 路徑在無 proxy 的環境不會被觸發。

## 曾考慮的替代方案

- **dev 期走 Vite `server.proxy`**：`NODE_USE_ENV_PROXY=1` 能讓 dev server 連外，但打包後無效，仍要另一條路，等於維護兩套。
- **架本地轉發 proxy**：對單機個人工具是多一個必須常駐的元件。
- **改用需金鑰或需開戶的來源**：與 ADR-0001 的理由衝突，且不解決 proxy 問題。
- **在 `MisProvider` 內各自處理傳輸**：少一個檔案，但 Yahoo provider 與對照表抓取會重複同一段邏輯。
