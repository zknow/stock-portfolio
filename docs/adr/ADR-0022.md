# ADR-0022：框架執行檔不納入版控，由 scripts\ensure-bin.bat 依 binaryVersion 自動下載

- 狀態：已決定
- 日期：2026-10-27

## 背景

`bin/neutralino-win_x64.exe` 是 Neutralinojs 框架執行檔，`neu run` 與 `neu build` 都需要它。先前它直接納入 git，clone 後即可執行，但有兩個問題：

- 二進位檔進版控會讓 repo 膨脹，每次框架升版都要再 commit 一份大檔。
- `npx neu update` 在部分網路環境會以 Node 的 https 路徑下載而 `ETIMEDOUT`，但 `curl.exe` 直接下載同一個 GitHub release 資產可以成功，因此不能依賴 `neu update` 作為唯一取得方式。`@neutralinojs/neu` 的 downloader 沒有 proxy 設定，無法由專案端切換。

## 決策

1. **`bin/` 加入 `.gitignore`，不再追蹤框架執行檔**，從索引移除 `bin/neutralino-win_x64.exe`。
2. **新增 `scripts\ensure-bin.bat`**：若 `bin\neutralino-win_x64.exe` 不存在，依 `neutralino.config.json` 的 `cli.binaryVersion` 組出下載網址 `https://github.com/neutralinojs/neutralinojs/releases/download/v{版本}/neutralinojs-v{版本}.zip`，以 `curl.exe -L -f` 下載到 `.tmp\`，以 `tar.exe` 解出後把執行檔複製到 `bin\`，最後清除暫存。已存在時直接略過。失敗時回傳非零結束碼。
3. **`start.bat` 與 `release.bat` 在切到專案根目錄後先呼叫 `ensure-bin.bat`**；失敗就暫停並結束，不進入 `neu run` 或 `neu build`。
4. **版本來源只有 `neutralino.config.json`**。`binaryVersion` 改了，下次執行就會下載對應版本；舊檔不會自動刪除，需要手動移除 `bin\` 後重跑。

## 理由

- 與 ADR-0010 的打包流程相容：`neu build` 仍從 `bin/` 取執行檔，只是改由腳本在執行前補齊。
- `curl.exe` 與 `tar.exe` 是 Windows 10 以上內建工具，不增加 npm 依賴，符合「不引入額外依賴」的既有約束。
- 用同一個 release 資產、同一個版本欄位，避免下載版本與 `neu` CLI 版本不一致。

## 後果

- clone 後第一次執行 `start.bat` 或 `release.bat` 需要網路，下載的 zip 會解出約 2.4 MB 的執行檔。
- 下載失敗時使用者需要自己看錯誤訊息排除網路問題，腳本不會替代 proxy 設定。
- 目前只在 `binaryVersion` 為 6.10.0 時實測過，其他版本依賴 GitHub release 資產命名規則不變。
- `bin/neutralinojs.log` 也由 `.gitignore` 排除，不再進版控。

## 曾考慮的替代方案

- **保留 exe 進版控**：clone 即用，但每次框架升版都會留下大型二進位歷史，且與 release 資產重複。
- **只依賴 `npx neu update`**：在本機實測 `ETIMEDOUT`，`@neutralinojs/neu` 不支援 proxy，無法作為唯一途徑。
- **要求使用者手動下載並解壓到 `bin\`**：與「clone 後直接執行」的需求不符。
- **改用 Electron 或 Tauri 等不需要此執行檔的框架**：屬於架構變更，超出本次範圍，已由使用者決定維持 Neutralinojs。
