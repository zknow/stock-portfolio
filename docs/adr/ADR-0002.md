# ADR-0002：庫存模型只存平均單位成本

- 狀態：已決定
- 日期：2026-10-16

## 背景

需求列出「設定單位成本」與「更新股票數量」兩項功能，並要求顯示總報酬與今日報酬。實作前必須決定庫存的資料形狀：

- **(a)** 只存「股數 + 平均單位成本」，由使用者自行填寫與修改
- **(b)** 存完整交易明細（每筆買進/賣出的日期、價格、股數），平均成本由系統推算

## 決策

**(a) 只存平均單位成本。**

一檔股票 = 一筆持股，以代號為唯一鍵，欄位為 `code`、`name`、`market`、`shares`、`averageCost`。不做交易明細、不做已實現損益、不做加權平均計算。

## 理由

- 需求用語是「設定單位成本」，語意即使用者提供數值，而非系統推導。
- 應用程式的目的是「檢視自己股票庫存」，不是記帳。存明細會連帶長出交易記錄 UI、買賣日期、加權平均、已實現損益、部分賣出處理，範圍膨脹成半個記帳軟體。
- 單一持股一筆記錄，代號即唯一鍵，讓新增/編輯/刪除都退化成兩個欄位的修改，資料模型與 UI 都最小。
- 使用者若真的需要新的平均成本，直接改數字即可，語意上等價。

## 後果

- 無法回答「這筆是何時買的」、「已實現損益多少」、「股利收了多少」。
- 無法從系統推導成本，`averageCost` 是使用者輸入值，需驗證為正數。
- **同一代號不允許重複新增**，因為多筆持股之間已無任何區別資訊。重複新增需拒絕並提示改用編輯。
- 平均單位成本為每股成本，單位與現價一致（皆為每股、非每張）。
- 代號新增後不可修改：變更代號等同刪除後重建。這避免了「改了代號還要重查對照表名稱」的錯誤路徑。

## 曾考慮的替代方案

- **存交易明細**：可算出加權平均成本與已實現損益，能支援部分賣出與股利。代價是需要交易記錄 UI、日期處理、買賣方向、多筆加總邏輯，且與「檢視庫存」的原始目的不符。若日後要轉型為記帳工具，這是必要的一步，屆時以 `schemaVersion` 遷移並新增 ADR。
- **同時存兩者**（明細為真、平均成本為快取）：兩份真相容易不同步，且複雜度最高。
- **允許同一代號多筆持股分開列示**：因為只存平均成本，多筆之間沒有可區分的資訊，列示多列只會造成重複，無實質意義。
