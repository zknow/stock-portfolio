# ADR-0026：neu run 改由 run-app.ps1 在 Job Object 中執行

- 狀態：已決定
- 日期：2026-10-27

## 背景

`start.bat` 以背景方式啟動 `neu run`，app 關閉後再呼叫 `kill.bat` 按程序名稱與路徑比對清除。這個做法只在正常路徑有效：若主控台被直接關閉或按 Ctrl+C，批次檔無法執行清理，`neu run` 與 Vite 會留在背景，使用者必須手動執行 `kill.bat`。

## 決策

1. **新增 `scripts\run-app.ps1`**：建立 Job Object 並設定 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`，以 `Start-Process` 啟動 `node node_modules\@neutralinojs\neu\bin\neu.js run`，再把該程序指派到 Job。腳本持有 Job 的 handle，等 app 出現後，等到 `neutralino-win_x64` 結束即返回。
2. **`start.bat` 改為**：`prepare.bat` → `kill.bat`（清除上次崩潰的殘留）→ `run-app.ps1` → `kill.bat`（收尾）。啟動失敗時 `run-app.ps1` 回傳非零並由 `start.bat` 暫停。
3. **`kill.bat` 保留**，用途為啟動前後的清理與手動清除，不再是唯一的收尾機制。

## 理由

- Job handle 隨 `run-app.ps1` 程序結束而關閉，核心會殺掉 Job 內的所有程序，涵蓋主控台關閉與 Ctrl+C，不依賴批次檔是否執行到最後。
- 子程序在 Job 指派後建立時自動繼承，`neu` 啟動的 Vite 與 WebView2 程序都在範圍內。
- 以 `Start-Process` 而非 `start /b`，讓 `-PassThru` 取得程序 handle 供指派。

## 後果

- 需要 PowerShell，Windows 10 以上內建。
- 程序在 `Start-Process` 與指派之間的極短時間內若已派生子程序，子程序不會在 Job 內；收尾的 `kill.bat` 仍會清理它們。
- 程序樹的最終清除以 Job 為準，`kill.bat` 的比對規則不變。
