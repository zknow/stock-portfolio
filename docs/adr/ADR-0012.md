# ADR-0012：編輯介面採就地編輯與系統原生確認對話框

- 狀態：已決定
- 日期：2026-10-16

## 背景

P4b 要實作 F2（新增）、F3（刪除）、F4（更新股數與成本）、F8（檢視 / 編輯模式切換）。規格只寫了行為（「股數與平均成本變為可編輯」「每列刪除鈕」「二次確認需顯示代號與名稱」），沒有指定介面形態。

專案硬性約束 5 禁止引入 UI 框架，因此任何對話框、modal、輸入遮罩都得自己寫，這讓「形態選擇」直接等於實作成本。

另一個既有事實是輪詢：`QuoteService` 每 5 秒廣播一次報價，`TableView.render` 每次都重建整個 `tbody`。任何把「使用者輸入」存在 DOM 值裡的設計都會被下一次輪詢清掉。

## 決策

1. **就地編輯**：編輯模式下，股數與平均成本的數值格可直接點擊變成輸入框。一次只編輯一列。提交為 Enter 或該列的「儲存」鈕，取消為 Esc 或「取消」鈕。
2. **新增表單展開於表格上方**，欄位順序與表格一致（代號 → 名稱 → 股數 → 平均成本）。輸入代號即查對照表帶出名稱與市場；查無時顯示「查無此代號」與預設收起的**強制新增**逃生門。
3. **刪除確認用 `Neutralino.os.showMessageBox`**（`YES_NO` + `Icon.WARNING`），標題含代號與名稱。
4. **編輯模式在表格最右加一欄「操作」**，放置刪除鈕與（輸入中時的）儲存 / 取消鈕；檢視模式整欄隱藏，F1 的 9 欄不變。
5. **輸入中的草稿由 `main.ts` 持有**（`EditDraft`），`TableView` 在重繪前記錄焦點所在的 `data-code` / `data-field` 與游標位置，重繪後還原。

## 理由

- 表格本身就是資料，就地編輯不需要切換視角，改一列只要「點格子 → 改數字 → Enter」。
- 原生對話框不必自刻 modal 的焦點鎖定、Esc 處理、點擊外部關閉與遮罩，程式碼量最少，且 Windows 上的行為與系統一致。這是一次刻意的不一致（系統樣式 vs 深色主題），換取實作量與焦點管理的正確性。
- 用獨立的「操作」欄而不是把按鈕塞進既有欄位：每個欄位語意保持單一，且檢視模式可以整欄隱藏，唯讀版面與 F1 完全一致。
- 草稿放在 `main.ts` 而不是讓 DOM 當狀態來源，是因為輪詢每 5 秒重建 `tbody`；草稿必須活得比 DOM 久。反過來說，焦點與游標是純 DOM 狀態，只能在重繪前後自行搬移，這也是 `TableView` 唯一需要知道輪詢存在的地方。
- 新增表單與表格同寬排列，是因為兩者的欄位概念相同，視覺上不必再學一套 modal 佈局。

## 後果

- 一次只能編輯一列。已有草稿時點擊其他列不會切換，避免默默丟掉輸入中的內容。
- 焦點還原依賴 `data-code` / `data-field` 屬性；若日後改成 DOM diff 式的局部更新，這段可以拿掉。
- 編輯模式的表格比檢視模式寬一欄，窄視窗下更容易出現水平捲動（ADR-0011）。
- 刪除確認對話框的樣式由作業系統決定，無法套用 `theme.css`。
- 新增成功後表單保持展開並清空，方便連續新增；`config/portfolio.json` 的寫入沿用既有的節流機制（`persist` 直接寫，偏好才節流）。

## 曾考慮的替代方案

- **統一的 modal 處理新增與編輯**：視覺一致，但要自刻對話框（含焦點鎖定與 Esc），且新增與編輯要各做一次表單。
- **表格下方常駐輸入列**：可省一個「開始編輯」的動作，但與表格距離遠，且需要先選列才知道在編輯哪一筆。
- **HTML 自製確認框**：樣式可與深色主題一致，但要多寫遮罩、焦點鎖定與 Esc 處理，成本不划算。
- **失焦即儲存**：少一層操作，但誤觸即寫檔，且與 F4「不合法則拒絕並保留輸入」的互動難以表達。
- **把刪除鈕放進代號欄**：不用多一欄，但代號欄會同時承載資料與操作，且檢視模式的欄位對齊會因為隱藏鈕而跳動。
