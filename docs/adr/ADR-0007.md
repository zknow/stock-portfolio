# ADR-0007：固定深色主題，紅漲綠跌

- 狀態：已決定
- 日期：2026-10-16

## 背景

需求列出「深色模式」。實作上有三種可能：

- 預設跟隨作業系統，使用者可手動覆寫並記住
- 只提供手動切換鈕
- 完全跟隨系統

另外，漲跌著色有兩套互斥的慣例：台股為**紅漲綠跌**，歐美市場為**綠漲紅跌**。

## 決策

1. **固定深色。** 不提供亮色主題，也不提供切換鈕。
2. 所有顏色集中於 `src/ui/theme.css` 的 CSS 變數（design token），不得在元件內寫死色碼。
3. **漲跌採台股慣例：紅漲綠跌。**

## 理由

- 這是一個個人使用、以看盤為目的的桌面工具。深色是使用者的實際偏好，不需要為不存在的亮色需求付出主題切換的複雜度：兩組 token、狀態持久化、系統偏好監聽、以及每個元件的雙色驗證。
- 保留 CSS 變數這一步的成本幾乎為零，但讓「日後想加亮色」變成「多一組變數」而非「掃過所有 CSS」。這是不犧牲簡潔的免費選項。
- **紅漲綠跌是本專案唯一會與開發者直覺衝突的地方。** 台灣股市與鄰近亞洲市場的慣例是紅色代表上漲（呼應「漲紅」的語感），與歐美相反。若不寫進文件，日後任何一次「修正配色」都會把它改錯。因此這個決定同時記於本 ADR 與 `docs/glossary.md`，並在 `AGENTS.md` 列為硬性約束。

## 後果

- `theme.css` 是唯一的色彩來源。`AGENTS.md` 規定顏色只能取自 CSS 變數，不得在元件內寫死色碼。
- 深色底上的紅綠必須同時滿足可讀性與色盲區辨。由於紅綠是最常見的色盲類型，**色彩不可作為唯一的漲跌訊號**：數值本身必須帶正負號，漲跌方向也要能由數字讀出。
- 不提供跟隨系統的邏輯，因此不需要監聽系統偏好變化，也不需要為此寫任何程式。
- 未持有任何顏色以外的 theme 狀態，`portfolio.json` 不需要保存主題欄位。
- 具體 palette 屬於設計階段的產出，將以 `frontend-design` 與 `ui-ux-pro-max` 決定，本 ADR 只鎖定「固定深色」與「紅漲綠跌」兩個約束。

## 曾考慮的替代方案

- **跟隨系統 + 手動覆寫**：兼顧直覺與可控，是通用應用程式的標準做法。代價是需要兩組完整 token、系統偏好監聽、狀態持久化，以及每個元件的雙模式驗證，而亮色模式在此專案沒有實際需求。
- **只有手動切換鈕**：實作比跟隨系統簡單，但仍需要第二組 token 與持久化。
- **綠漲紅跌（國際慣例）**：與 Yahoo Finance 等國際來源一致，但對台股使用者的閱讀習慣是反的，會造成當下的誤讀。
- **不用顏色，只用正負號**：對色盲最友善，但犧牲了看盤時一眼判讀的速度。改以「顏色 + 正負號並存」同時滿足兩者。
