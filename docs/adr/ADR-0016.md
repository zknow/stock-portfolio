# ADR-0016：欄寬貼齊內容，最小視窗尺寸由內容自然寬度推得

- 狀態：已決定
- 日期：2026-10-18

## 背景

ADR-0011 的前提是「表格是 9 欄橫向排列，內容本身的自然寬度本來就接近 1100」，所以把縮放下限夾在 0.85（對應視窗寬 935），窄於 935 之後超出的寬度由表格水平捲動消化。

ADR-0015 把四個報酬欄改成金額／比率二選一之後，這個前提消失：

- 欄位由 9 欄降為 7 欄（編輯模式 8 欄），內容自然寬度降到約 500；
- `table { width: 100% }` 把欄位平均拉開填滿視窗，使用者看到的是欄與欄之間的大片空白，而不是一個可以縮小的介面。

使用者回報：欄位減少後應該讓欄寬貼齊，介面才能縮得更小；左右縮放的最小值必須能顯示所有欄位，不要靠水平捲動；上下縮放要有合理的比例。

前一版的最小視窗 700×480 與內容實際需要的 500×345 之間差了 200，而且 480/760 = 0.63 與縮放下限 0.85 不是同一個基準。

## 決策

1. **欄寬貼齊內容**：`table { width: max-content }`。表格寬度由資料決定，不隨視窗拉開。這讓「內容需要多寬」從估計值變成可以量的實測值。
2. **最小視窗寬度由內容推得**：量測內容在縮放下限（`MIN_SCALE = 0.85`）時的自然寬度（把 `--scale` 固定在下限、`.app` 設成 `width: max-content`，讀 `getBoundingClientRect().width`），加上垂直捲軸保留區後即為最小寬度。取工具列、表格、總計列、狀態列的最大值。
3. **垂直捲軸保留區固定存在**：`.board { scrollbar-gutter: stable }`。捲軸出現與否不改變客戶區寬度，最小寬度不會少算一個捲軸寬。
4. **最小視窗高度按基準比例推導**：`minHeightFor(minWidth) = round(minWidth × 760 / 1100)`，視窗形狀與 1100×760 的設計一致。
5. **內容改變時重算**：持股、編輯模式、報酬顯示模式都會改變自然寬度，`refresh()` 之後重算，值有變才重新套用 `setSize`。
6. **新增表單不列入量測**：表單列可換行（`flex-wrap`），不會造成水平溢出；列入量測會把最小寬度撐到約 700。量測時把表單寬度設為 0，不能改 `hidden`（會讓輸入框在輪詢重繪時失焦）。
7. 此決策**取代 ADR-0011 的「低於下限由表格水平捲動消化」**，並取代其所引用的 700 下界。ADR-0011 本文依專案規則不修改。

## 理由

- 欄寬貼齊之後，最小視窗寬度可以直接由實測的內容寬度推得，不必再靠「1100 的 0.85 倍」這種與內容無關的換算。
- 水平捲動是前一個決策的產物，不是使用者要的功能：它把「視窗很窄」與「看得到資料」變成二選一。改成由內容決定最小寬度之後，使用者能縮到的下限就是「所有欄位都還在」的那條線，捲動不會發生，也就不需要這個機制。
- 高度按設計比例推導，是因為縮放下限已固定字級：字級不再跟著視窗縮放，視窗形狀就該沿用設計比例，而不是各自為政的 700×480。
- `scrollbar-gutter: stable` 的著眼點是正確性而不是美觀：列數多到出現垂直捲軸時客戶區會少一個捲軸寬，最小寬度若沒把這塊算進去，縮到最小時最右欄會被切掉。
- 量測成本是每次 `refresh()` 兩次強制重排（輪詢每 5 秒一次），`setSize` 只在值真的變動時呼叫，不需要額外的監聽或快取。

## 後果

- **最小視窗尺寸不再是常數**：`src/main.ts` 的 `MIN_WIDTH = 700` / `MIN_HEIGHT = 480` 移除，改由 `measureMinSize()` 推得。以 1 檔持股實測：檢視模式 500×345（報價尚未載入時 483×334）、編輯模式 564×390。
- 最小寬度隨資料變動：股數、平均成本或報價欄位越寬，能縮到的下限越大；刪掉寬的持股之後下限會縮小。內容變寬時視窗會被推到新的下限（不裁切），變窄時要等下一個 `refresh()` 才會放寬。
- `portfolio.json` 的 `windowWidth` / `windowHeight` 若小於推得的尺寸，啟動時會被抬到下限（F14 既有行為，改成對動態值生效）。
- `neutralino.config.json` 的 `minWidth` / `minHeight` 只在應用程式套用尺寸前有效，之後由 `setSize` 覆蓋；該檔不再需要與程式碼常數一致。
- 表格不再填滿視窗寬度，視窗較寬時右側留空——這是「貼齊」的直接結果。
- 縮放只在視窗寬 935 以上才有變化（低於 935 一律 0.85，ADR-0011 的夾限不變），因此 500–935 之間把視窗拉寬只會增加右側留白。

## 曾考慮的替代方案

- **固定欄寬（`colgroup` + `table-layout: fixed`）**：最小寬度可精確推導、與資料無關，但要多養一組欄寬常數，內容超過欄寬時還會被裁切。自然寬度既然量得到，就不需要人工指定。
- **保留 `width: 100%`，只縮小欄距**：欄位仍隨視窗拉開，能省下的寬度有限，等於沒解決問題。
- **保留水平捲動，只把下限放寬**：使用者要的是「縮到最小時所有欄位都在」，捲動不會把欄位帶回畫面。
- **不設最小寬度，讓視窗縮到任意小**：欄位會被裁掉，資料看不到。
- **量測時把新增表單一起算進去**：表單可換行，不會造成水平溢出，算進去只會讓最小寬度被一個可自動折行的區塊決定。
- **最小高度沿用 480**：與縮放下限的基準不同（480/760 = 0.63 對 0.85），視窗形狀會隨寬度變形而變。
