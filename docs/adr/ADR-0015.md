# ADR-0015：報酬欄的顯示模式切換與投組今日報酬率

- 狀態：已決定
- 日期：2026-10-18

## 背景

F1 原本規定檢視模式固定 9 欄，其中四個報酬欄兩兩是同一個指標的兩種表示：`總報酬金額` / `總報酬率` 與 `今日報酬金額` / `今日報酬率`。F12 的投組總計列同樣同時顯示總報酬金額與總報酬率。

使用者要求改為可切換：「讓我切換我要以金額顯示還是百分比顯示，預設百分比，這樣顯示的欄位就可以從 4 節省至 2」。

四個報酬欄的資料在 `domain/pnl.ts` 本來就都有算（`PnlRow` 的四個欄位），只是顯示哪兩個的問題。真正的缺口在總計列：`PnlTotals` 有 `totalReturnRate`，但**沒有今日的比率**——F12 只定義了 `總報酬率 = 總報酬金額 / 總成本`，沒有任何一條公式可以算出投組層級的今日報酬率。新增報酬率公式依硬性約束 3 必須先有 ADR，即本檔。

## 決策

### 1. 顯示模式：`rate`（預設）/ `amount`

- 表格的兩個報酬欄改為「金額」或「比率」二選一，欄數由 9 降為 7。
- 欄頭文字跟著模式：`rate` 為「總報酬率」「今日報酬率」，`amount` 為「總報酬金額」「今日報酬金額」。
- 逐列金額維持 F6 的既有格式，不加 `NT$` 前綴；`NT$` 只出現在總計列。
- 入口為工具列的一顆切換鈕，檢視模式也看得到（這不是編輯功能）。鈕面顯示當前單位（`%` 或 `NT$`）。
- 模式存進 `config/portfolio.json` 的 UI 偏好（F14），欄位名 `returnDisplay`，預設 `rate`。
- `schemaVersion` **維持 1**：新欄位是可選的，舊檔缺欄位或值不合法時回預設值，讀取不會失敗，屬向後相容，沒有需要遷移的語意變更。

### 2. 投組今日報酬率

```
投組今日報酬率 = 今日總報酬 / 昨日總市值
昨日總市值     = Σ(昨收 × 股數)，只累加「昨收不缺」的持股
```

等價於逐列今日報酬率以**昨收市值**為權重加權平均。分母為 0（無持股，或全部持股都缺昨收）時為缺值，顯示 `—`。

與總報酬率的差異只在分母：總報酬率除以「現在的成本」，今日報酬率除以「昨天的市值」，兩者都是先加總再相除，不是逐列比率的平均。

### 3. 切換時排序鍵對映

切換模式時，若當前排序鍵落在被隱藏的欄位，改寫成同組的另一個：`totalReturn` ↔ `totalReturnRate`、`todayReturn` ↔ `todayReturnRate`，方向不變。其他排序鍵（含不顯示的 `marketValue`）不受影響。

## 理由

- 兩兩重複的欄位各佔一份寬度，互斥顯示可直接省下兩欄，是使用者要的效果。
- 欄頭寫「金額」或「率」而不是固定的短標題，讓每一欄自我說明；否則 `12,345` 與 `12.35%` 只靠有無 `%` 區分，掃視時容易誤讀。
- 總計列跟著切換：不切的話 `%` 模式的總計列仍會出現金額，與表格的顯示模式不一致。
- 今日報酬率定義為「今日總報酬 ÷ 昨日總市值」而不是除以總成本：這樣它與逐列的今日報酬率是同一個基準（都以昨收為分母），投組層級的數字才是逐列數字的加權平均，可以直接對照。
- 排序鍵必須對映，否則會出現 F13 明確禁止的狀態：欄頭沒有排序指示，但資料確實照某個不可見的鍵排序。金額與比率的排序結果不同（比率是每股相對值，金額受股數放大），不處理會讓使用者以為排序壞了。
- 對映是等價交換而非重置：`marketValue` 這類與報酬欄無關的排序鍵不該被無關的切換打斷。

## 後果

- 使用者無法同時看到金額與比率，要看另一個必須切換。這是換得兩欄寬度的代價，也是使用者要求的取捨。
- 切換會寫入 `portfolio.json`（沿用 500 ms 節流）。`portfolio.json` 損毀時，切換仍即時生效但不寫回——沿用 `scheduleSave()` 在 `loadError` 非 null 時直接返回的既有保護，切換鈕因此不隨 `setEnabled(false)` 停用。
- `PnlTotals` 新增 `todayReturnRate`，`computeTotals` 多累加一個分母（以 `marketValue - todayReturn` 求得昨日市值，不需回頭讀 quote）。
- 投資組只有一檔、且該檔缺昨收時，分母為 0，總計列的今日報酬率顯示 `—`，與逐列一致。
- 偏好相容性：舊版 `portfolio.json` 沒有 `returnDisplay`，讀入後為 `rate`，第一次寫檔才補上欄位。

## 曾考慮的替代方案

- **維持 9 欄**：資訊最完整，但使用者要的就是省欄位，且兩兩並列在窄視窗下擠壓。
- **三態（金額 / 比率 / 兩者都顯示）**：多一個狀態與一條測試路徑，而「兩者都顯示」就是現狀，可隨時用切換取代。
- **按鈕文字顯示「按下去會切到什麼」**（比照 F8 的模式鈕顯示「編輯 / 完成」）：切換鈕同時要兼任單位指示，顯示當前單位（`%` / `NT$`）較能說明欄位與總計列現在是什麼。模式鈕的「顯示動作」慣例不套用到這裡。
- **存進獨立設定檔而非 `portfolio.json`**：違反 ADR-0004 的單一 JSON 決策，且要多一套讀寫與損毀處理。
- **`%` 模式的總計列不顯示今日報酬率**：會讓投組層級少一個逐列都有的指標，且與使用者要的「切換」不對稱。
- **切換時把排序重置為預設市值遞減**：不必處理對映，但會在使用者只是換個顯示單位時默默丟掉排序選擇。
