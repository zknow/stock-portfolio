# ADR-0019：加權指數隨持股報價同批取得，顯示於狀態列右側

- 狀態：已決定
- 日期：2026-10-20

## 背景

使用者要在狀態列右側、與「更新於 HH:mm:ss」同一列看到發行量加權股價指數，格式為現價、漲跌與漲跌幅，並沿用紅漲綠跌：

```
加權指數 46,662.77 ▽158.10 (-0.34%)
```

指數不是持股，沒有股數與成本，不能進 `Holding`，也不應計入 F12 的任何報酬或總計。既有的 `QuoteBatch` 只有持股報價，狀態列也沒有放指數的位置。

## 決策

1. **`QuoteBatch` 增加 `index: MarketIndex | null`**。`MarketIndex` 只含 `price`、`previousClose`、`dataDate`，與 `Quote` 一樣是來源無關的正規化型別，`domain/` 不接觸任何 MIS / Yahoo 欄位名。
2. **與持股報價同一次嘗試取得**，不新增輪詢排程：
   - MIS：`ex_ch` 固定附加 `tse_t00.tw`，仍是一個批次請求。解析時 `c === "t00"` 的項目放進 `index`，不混入 `quotes`。
   - Yahoo 備援：持股逐檔抓 `.TW` / `.TWO`，另外抓 `^TWII`，兩者以 `Promise.all` 同時進行。
3. **指數失敗不影響持股報價**：MIS 沒回 `t00` 時 `index` 為 `null`；Yahoo 的 `^TWII` 非 200 或解析失敗也回 `null`。持股報價的成功／失敗、降級與回試判定完全不變。
4. **顯示於狀態列最右**：`.status .index { margin-left: auto }`，與左側的更新時間、來源標籤同一列。「加權指數」標籤與「MIS 即時」同色（`--text-dim`），指數現價為白色（`--text`）。上漲紅色 `△`、下跌綠色 `▽`、平盤不帶符號；漲跌與漲跌幅沿用既有格式（正數帶 `+`）。顏色不是唯一訊號，方向符號必須存在（ADR-0007）。
5. **缺值不顯示**：沒有指數或沒有現價時整個區塊略過；只有缺昨收時顯示指數現價。

## 理由

- 指數與持股更新頻率完全相同（5 秒、交易時段內），獨立排程只會多一組計時器、來源狀態與重疊請求的保護。
- MIS 支援同一個 `ex_ch` 批次放入指數，額外成本只是 URL 多一個通道；Yahoo 沒有批次端點，但仍可與持股請求並行，不增加一輪等待。
- 把指數放進 `QuoteBatch` 讓 `QuoteService` 的重繪與狀態廣播自然帶上它，`main.ts` 不必另外持有第二份報價狀態。
- 指數失敗若讓整個批次失敗，會把輔助資訊的可用性綁到持股報價與降級計數上，代價遠大於收益。

## 後果

- `QuoteBatch` 的所有建構點都必須提供 `index`（兩個 provider）。
- 狀態列寬度增加，`measureMinSize()` 量到的內容自然寬度跟著變寬，視窗會自動貼合（ADR-0016）。
- 空投組時 `QuoteService` 仍不發請求（既有行為），因此沒有指數可顯示。
- `indexSummary()` 是純函式，漲跌、平盤、缺值由 vitest 覆蓋；實際 DOM 排列與顏色仍需實機確認。

## 曾考慮的替代方案

- **把指數當成一筆持股／`QuoteTarget`**：會出現在持股清單、參與缺值統計與總計排除，還要處理 Yahoo 的 `.TW` 對照，語意錯誤。
- **`QuoteService` 另開一條指數輪詢**：多一組失敗計數與計時器，且與持股輪詢可能同時打到 MIS，違背批次請求的限流手段。
- **狀態列自行呼叫報價 API**：違反硬性約束 1（UI 不得直接呼叫報價 API），也把來源解析帶進 `ui/`。
- **只在 MIS 提供指數、降級時留空**：降級可能持續數分鐘，狀態列會出現無故消失的區塊；Yahoo 的 `^TWII` 成本只是一次並行請求。
