# ADR-0001：報價來源採 MIS 即時報價，Yahoo 為備援

- 狀態：已決定
- 日期：2026-10-16

## 背景

應用程式需要「即時追蹤股價」與「今日報酬」，因此每個持股需要兩個數值：**現價**與**昨收**。這是唯一會決定整體架構的外部約束。

盤點台股報價來源並實測（2026-10-16 盤中）：

| 來源 | 金鑰 | 實測延遲 | 限流 | 提供昨收 | 可從桌面呼叫 |
|---|---|---|---|---|---|
| `mis.twse.com.tw` | 免 | 真即時 5–13 秒 | 官方無規定；社群慣例 3 次/5 秒 | 是（`y`） | 是，無需 UA / Referer / cookie |
| Fugle MarketData | 免費註冊 | 真即時 | 60 次/分；WebSocket 限 5 檔 | 是（`previousClose`） | 是 |
| Yahoo `v8/chart` | 免 | 延遲約 20 分鐘 | 未公開 | 是（`chartPreviousClose`） | 是 |
| TWSE / TPEx OpenAPI | 免 | 僅前一交易日 | 未公開 | 否，需 `Close − Change` 推算 | 是 |
| FinMind | 免費 300 次/時 | 即時僅贊助者 | 300–600 次/時 | 否 | 是 |
| Shioaji / 富邦 Neo / 元大 SPARK | 需開證券戶 | 真即時 | — | 是 | 是 |
| TWSE 官方延遲 20 分鐘源 | — | 延遲 20 分鐘 | — | — | **付費 NT$180,000 / 半年** |

實測 MIS 的關鍵性質：

- 一個請求可攜帶整個持股清單（30 檔一次、21 KB、2.8 秒）
- 直接提供昨收（`y`）
- 實測 25 次請求 / 20.6 秒（約 6 次/5 秒）全部 200，未遭封鎖，僅延遲略升
- 13:30 收盤後照常回應，`z` 為收盤價、`t` 為 `13:30:00`
- 對錯誤代號或錯誤前綴**不回錯誤**，而是回傳佔位物件 `{"tv":"-","s":"-","c":"","z":"-"}`，插入於陣列原位置

## 決策

1. **主來源為 MIS 即時報價**（`mis.twse.com.tw`），批次輪詢。
2. **備援為 Yahoo Finance `v8/chart`**，延遲約 20 分鐘。
3. 定義 `QuoteProvider` 介面，MIS 與 Yahoo 各為一個實作，由 `QuoteService` 決定使用哪一個。
4. **不採用**官方 20 分鐘延遲源、Fugle、FinMind、券商 API。
5. **不建立官方 EOD 校正層**，直接信任 MIS 的昨收。
6. 代號對照表由官方 OpenAPI 每日產生：TWSE `STOCK_DAY_ALL` + TPEx `tpex_mainboard_quotes`。

## 理由

- MIS 是唯一同時滿足「免費、零註冊、真即時、一次請求涵蓋全部持股、直接提供昨收」的來源。其餘來源都至少在一個軸上妥協：Fugle 需註冊且免費層限流嚴格（40 檔約需 40 秒一輪、WebSocket 只給 5 檔），Yahoo 延遲 20 分鐘，官方 OpenAPI 盤中只能拿到前一交易日。
- 排除官方付費源的理由是成本（NT$180,000 / 半年）與個人工具規模完全不成比例。
- 排除券商 API 的理由是需要開戶與憑證，對「唯讀檢視庫存」是過度摩擦，且本專案不下單。
- MIS 的非官方性質是主要風險，但可透過介面隔離吸收：格式變動只需改 `MisProvider` 一個檔案。
- 批次輪詢本身就是遵守社群限流慣例的手段（40 檔仍是一次請求）。
- 不做 EOD 校正層：多一個模組、多一支 API、多一個排程，換到的是「MIS 昨收可能出錯」這個低機率情境的保險。MIS 若整體失效，已有 Yahoo 備援涵蓋。

## 後果

- `QuoteService` 必須實作失敗計數、降級（連續 3 次）與回試（每 5 分鐘）。
- 狀態列必須顯示資料來源與更新時間，降級時需標示「延遲約 20 分」。
- `MisProvider` 是唯一允許知道 MIS 欄位名的檔案。
- 必須處理 MIS 的佔位物件（`c === ""`）與當日無成交（`z === "-"`）兩種非錯誤的異常狀態。
- 對照表更新失敗時沿用舊快取，不阻擋啟動。
- 若 MIS 無預警消失，替換成本限縮在一個 provider 實作。

## 曾考慮的替代方案

- **Fugle 免費層**：有官方文件與商業授權，穩定度最高，但需註冊、60 次/分對 40 檔需 40 秒一輪、WebSocket 僅 5 檔訂閱。若日後要求授權正當性或穩定性，這是首選替代。
- **Yahoo 作為主來源**：免金鑰、實作最簡單、不碰非官方端點，但 20 分鐘延遲與「即時追蹤」需求直接衝突。
- **官方 OpenAPI 作為主來源**：完全無授權顧慮，但盤中只能取得前一交易日收盤價，等於沒有即時報價。
- **自行建立 EOD 校正層**：正確性更高，但複雜度不划算。
- **不設 provider 介面，直接在 UI 呼叫 MIS**：少一層抽象，但唯一脆弱的依賴會散落各處，且違反分層原則。
